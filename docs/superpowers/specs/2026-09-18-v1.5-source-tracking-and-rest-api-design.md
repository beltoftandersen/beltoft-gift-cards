# v1.5.0: Gift Card Source Tracking + REST API — Design

## Problem

1. At redemption, an order stores only the gift card code and amount. An accounting system cannot tell whether the redeemed card was **paid** (a liability being settled, no revenue effect) or **free** (a real discount / marketing cost).
2. There is no way to read or manage gift cards from outside WordPress.

## Decisions

### Source tracking
- New column `source varchar(20)` on `{prefix}bgcw_gift_cards`. Values:
  - `order` — created from a shop order (paid).
  - `paid_offline` — created manually for a sale outside the shop (paid).
  - `promotion` — created manually as a giveaway (free).
  - `compensation` — created manually as goodwill / refund replacement (free).
- "Paid" = `order` or `paid_offline`. Exposed as computed `is_paid`.
- DB version 1.2 → 1.3. Migration backfills existing rows: `order_id IS NOT NULL` → `order`; otherwise → `promotion` (assumption: pre-1.5 manual cards were free; the REST API can correct individual rows).
- Manual creation (admin form and REST) requires a source from the three manual values.

### At-rest data on the redeeming order
Written on `woocommerce_checkout_order_created` (fires for classic and block checkout) in `OrderProcessor::save_pending_deductions`, on each gift-card **coupon line item**:
- `bgcw_gift_card_id` (int), `bgcw_source` (string), `bgcw_is_paid` (`yes`|`no`), `bgcw_source_order_id` (int, 0 when none).
Keys are not underscore-prefixed so every exporter and the WC REST orders endpoint show them under `coupon_lines[].meta_data`.

Written once deduction succeeds in `OrderProcessor::deduct_gift_card_balances`, on the order:
- `_bgcw_paid_redeemed_total` and `_bgcw_free_redeemed_total` (decimal strings, 2 dp). Sum of successfully deducted amounts grouped by `is_paid`. Refunds are visible as separate transactions and do not alter these totals.

### REST API
- Namespace `wc-bgcw/v1`. The `wc-` prefix makes WooCommerce consumer key/secret authentication work; WordPress application passwords and cookie+nonce also work.
- Permission: `current_user_can( 'manage_woocommerce' )`, filterable via `bgcw_rest_permission( bool $allowed, WP_REST_Request $request )`.
- Routes:
  - `GET    /gift-cards` — params `page`, `per_page` (max 100), `status`, `source`, `search`, `orderby`, `order`. Headers `X-WP-Total`, `X-WP-TotalPages`.
  - `POST   /gift-cards` — `amount` (required, > 0), `source` (required, manual value), `recipient_name`, `recipient_email`, `sender_name`, `sender_email`, `message`, `expires_at` (ISO 8601 or null to override default), `send_email` (bool, default true; only sends when `recipient_email` set).
  - `GET    /gift-cards/{id}`
  - `GET    /gift-cards/code/{code}`
  - `PATCH  /gift-cards/{id}` — `status` (`active`|`disabled`), `source`, `recipient_name`, `recipient_email`, `sender_name`, `sender_email`, `message`, `expires_at`.
  - `POST   /gift-cards/{id}/adjust` — `amount` (non-zero, positive credits, negative debits), `note` (string). Debits use the atomic deduction; insufficient balance → 400.
  - `GET    /gift-cards/{id}/transactions`
  - `DELETE /gift-cards/{id}` — requires `force=true`; deletes the card and its transactions.
- Gift card representation: `id, code, initial_amount, balance, currency, status, source, is_paid, sender_name, sender_email, recipient_name, recipient_email, message, order_id, customer_id, expires_at, created_at`. Amounts are decimal strings, dates ISO 8601 UTC or null.
- Transaction representation: `id, gift_card_id, order_id, type, amount, balance_after, note, created_at`. `note` is the localized text from `TransactionNote::format()`.

### Admin UI
- Manual-create form gets a required "Source" dropdown.
- Gift card list: Order column shows the source label instead of "Manual" for cards without an order; new `source` filter param supported by `Repository::build_where`.

### Testing
No PHPUnit exists. A lightweight harness `tests/` runs PHP test files through `wp eval-file` inside the `wp_app` container against the real database; each test creates and deletes its own rows. `tests/` and `docs/` are excluded from the distributed zip and from Plugin Check via `--exclude-directories=tests,docs`.

## Out of scope
- Store-side (customer) REST endpoints.
- Changing how redemption is recorded (coupon line) — see conversation 2026-09-18.
- Editing card source from the admin list UI (use REST).
